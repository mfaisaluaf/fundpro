## Issues Fixed

### 1. Payout History — Partner Detail Modal Showing "No Data"
**File:** `backend/server.js` — `/api/dashboard/partner/:id`
**Problem:** The endpoint always filtered `WHERE ps.pending_withdrawal = 1`. For historical paid months (all rows have `pending_withdrawal = 0`), it returned empty transactions, causing "No data for this month." in the History page partner modal.
**Fix:** Added `month_year` query param support. When `month_year` is provided (History page), filter by `t.month_year = ?` with no pending filter. Without `month_year` (Dashboard), keep `pending_withdrawal = 1`.

### 2. April 2024 Reconciliation — Missing Owner Cut Payouts
**Problem found:** Faisal and Umair's owner cuts were never included in their April 2024 withdrawals.
- Faisal owed: **Rs 41,611** (owner cut from txn 31 — Project Management Dallas)
- Umair owed: **Rs 177,532.50** (owner cuts from txns 28+29 — Assetize)
- Total shortfall: **Rs 219,143.50**

**Root cause:** The Pay Now endpoint (`/api/pay-now`) had this logic:
```javascript
// Owner-cut-only: no partner_shares AT ALL
WHERE owner_partner_id = ? AND pending_withdrawal = 1
AND NOT EXISTS (SELECT 1 FROM partner_shares WHERE transaction_id = transactions.id)
```
This only captured owner_cut for transactions with zero partner_shares rows. When partner_shares existed (for the dist% portion), the owner_cut in `transactions.owner_cut_amount` was silently skipped.

Note: Usman's txn 30 worked fine because his `partner_shares.share_amount` had owner_cut embedded (417,775.65 = 203,793 + 213,982.65). Umair/Faisal's transactions stored only the dist% in share_amount.

**Fix (data):** Inserted correction withdrawal records:
- Withdrawal id 35: Faisal, Rs 41,611, date 2024-04-30, month_year 2024-04
- Withdrawal id 36: Umair, Rs 177,532.50, date 2024-04-30, month_year 2024-04

**Fix (code):** Added `ownerCutSeparate` to Pay Now logic in `backend/server.js`:
```javascript
const ownerCutSeparate = db.prepare(`
  SELECT COALESCE(SUM(t.owner_cut_amount), 0) as total
  FROM transactions t
  INNER JOIN partner_shares ps ON ps.transaction_id = t.id AND ps.partner_id = ?
  WHERE t.owner_partner_id = ? AND t.pending_withdrawal = 1
    AND ps.pending_withdrawal = 1
    AND ps.share_amount < t.owner_cut_amount
`).get(p.id, p.id).total;
const total = sharesTotal + ownerOnlyTotal + ownerCutSeparate;
```

### 4. RE Balance Mismatch — Dashboard vs RE Page
**Problem:** Dashboard showed Rs 19,773 but RE page showed Rs 217,502.
**Root cause:** `/api/retained-earnings` `net_retained` formula was missing two components:
- `+totalREConverted` = Rs 306,606 (FCY→PKR conversions from `re_transfers`)
- `-totalREWithdrawn` = Rs 504,335 (transactions using RE as income source)

**Fix (`backend/server.js`):**
Added two queries before `netRetained` calculation in `/api/retained-earnings`:
```javascript
const totalREConverted = db.prepare("SELECT COALESCE(SUM(to_amount),0) as t FROM re_transfers WHERE transfer_type='fcy_to_pkr' AND to_currency='PKR'").get().t;
const totalREWithdrawnDirect = db.prepare("SELECT COALESCE(SUM(t.pkr_amount + COALESCE(t.deduction_amount,0)),0) as t FROM transactions t JOIN income_sources s ON s.id=t.source_id WHERE s.is_re_source=1").get().t;
const netRetained = total + totalREConverted - totalDistributedBack - totalFromReExpenses - totalREWithdrawnDirect;
```
Also added `total_re_converted: totalREConverted` to the response JSON.

## Key Architecture Notes (TechyNex)

### partner_shares.share_amount inconsistency
- Some transactions embed owner_cut into `share_amount` (Usman's Bilweb txn)
- Others store only dist% in `share_amount`, keeping owner_cut separate in `transactions.owner_cut_amount`
- The dashboard display formula handles both via:
  ```sql
  CASE WHEN t.owner_partner_id = ? AND ps.share_amount >= t.owner_cut_amount
    THEN ps.share_amount - t.owner_cut_amount  -- extract embedded owner cut
    ELSE ps.share_amount END as my_dist_share
  ```
- Pay Now now handles both cases correctly with the `ownerCutSeparate` addition

### RE Balance Formula (both endpoints now match)
```
balance = retained_earnings_sum + fcy_to_pkr_conversions
        - retained_distributions - from_re_expenses - re_source_transactions
```

### Dashboard Partner Modal vs History Partner Modal
- Both use `/api/dashboard/partner/:id`
- Dashboard: no `month_year` param → `WHERE pending_withdrawal = 1` (queued only)
- History: with `month_year` param → `WHERE t.month_year = ?` (historical, all)
