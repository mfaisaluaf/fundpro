## Bug Fixes & Features

### 1. Total Paid Out logic wrong in Payout History
**Problem:** "Total Paid Out" card in payout history detail showed Rs 445,233 but sum of partner cards = Rs 486,832. Difference = Rs 41,599 = Faisal's owner cut (withdrawal record missing).

**Root cause:** `totalPaid` used `detail.withdrawals.reduce(sum of amount_pkr)` — actual DB withdrawal records. But partner cards showed `total_earned = ownerCut + distShare` computed from transaction shares. Mismatch when some owner-cut withdrawals not recorded.

**Fix:**
- `History.jsx:16` — changed `totalPaid` to `detail.partners.reduce((s, p) => s + Math.round(p.total_earned), 0)`
- `server.js` list endpoint `/api/history` — removed raw `SELECT SUM(amount_pkr) FROM withdrawals` for `total_paid`; now computed as `partnerSummary.reduce((s, p) => s + p.total_earned, 0)` after partners are built
- Added `Math.round()` per partner to prevent ±1 Rs rounding difference between Total Paid and sum of individual cards

### 2. Dashboard "Total Earnings" and "Added for Payout" breakdowns removed
**User request:** Remove per-source breakdown rows from both top cards.
- Removed `income_breakdown` rows from "Total Earnings of the Month" card
- Removed `queued_breakdown` rows from "Added for Payout" card
- "Added for Payout" amount changed from `data.total_queued_for_payout` (raw shares sum) to `data.partners.reduce((s, p) => s + Math.round(p.total_earned), 0)` — same logic as payout history

### 3. RE Breakdown for queued payout on Dashboard
**User request:** Show retained earnings table on Dashboard (same as payout history) for queued payouts.

**Backend:** Added `queuedRetained` query — finds pending transaction IDs (from `partner_shares.pending_withdrawal=1` + `transactions.pending_withdrawal=1`), fetches `retained_earnings` linked to those, enriches each with its `retained_distributions` + `retained_distribution_items` (with partner names). Returned as `queued_retained` in API response.

**Frontend:** Added RE table (Date / Notes / Retained / Distributed Back) in Dashboard.jsx. Initial placement was between partner cards and income table — then user asked to swap: income first, then RE. Final order:
1. Partner Cards
2. Income Transactions table
3. Retained Earnings table (queued_retained)
4. Expenses table
